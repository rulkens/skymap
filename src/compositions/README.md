# compositions/ — the composition root

The only folder that may import more than one Layer. It names the app's Layer tuple (`app.ts`) and builds every **registry**, a collection with a row per Layer or per Layer-owned kind, from the Layers' contract members ([ADR 0013](../../docs/adrs/0013-registries-built-from-layer-contributions.md)).
Two mechanisms, no third: a **static** registry is a plain member collected by import into one `app<Name>.ts` here; a **runtime** one is composed in `createLayers` (`src/services/engine/phases/createLayers.ts`) from a runtime-bound member and read off `EngineState`.
The ledger below is the overview. **Consolidated?** is DONE when the registry is derived from the Layers, and **TODO** while a row per Layer or per kind is still written in core: `core-built` means core imports Layers to build it, `hand-written per kind` means core keys a table, `switch` or union on the kinds by hand. Every TODO row names where its migration is tracked; a row leaves the TODO state only by deleting the core table, never by relabelling. `tests/conventions/layerImportBoundary.test.ts` requires every core file that still imports a Layer to be a row here, so the `core-built` rows cannot drift. Tally on 2026-10-30: 9 DONE, 30 TODO.
Core readers = files under `src/` outside `compositions/` found by `git grep -l` on the module path (2026-10-29; `APP_SOURCE_REGISTRY` also excludes `src/layers/`, whose own-row reads are backlog J16); runtime rows are read off `EngineState` instead.
