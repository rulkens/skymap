# Atmosphere Rendering

**Status:** Proposed (2026-05-09 amendment) — see [`decisions/0010-earth-opening.md`](../decisions/0010-earth-opening.md).
**Used by:** [`shells/00a-earth-opening.md`](../shells/00a-earth-opening.md) only.
**Sister docs:** [`data/11-earth-textures.md`](../data/11-earth-textures.md) (atmosphere LUT generation), [`rendering/03-volumetric-effects.md`](03-volumetric-effects.md) (shared raymarching framework — atmosphere does NOT use it; this is a fundamentally simpler technique).

## Goal

Render the sunset → night-sky color gradient at the tour's open and the night-sky → sunrise gradient at the tour's close. Make the user say "oh" before they have time to think.

This document specifies a sky shader that is:
- **Cheap** — under 1 ms per frame on integrated mobile GPUs.
- **Physically motivated** — colors come from a precomputed scattering LUT, not from artist-chosen gradients (though the LUT is tone-mapped so the result reads cinematically).
- **Single-purpose** — only used in shell 0a. We are explicitly NOT building a general-purpose atmospheric scattering system.

## Why not the existing volumetric framework

[`rendering/03-volumetric-effects.md`](03-volumetric-effects.md) describes a shared raymarching framework for the Sun corona, X-ray halos, and dark-matter density volume. The atmosphere is *not* one of those.

A real atmosphere needs to integrate scattering along view rays through a vertically inhomogeneous medium with two scattering species (Rayleigh + Mie) and a directional light source (the Sun). That is its own physical model, distinct from "raymarch a scalar density field." Forcing it through the volumetric framework would either bloat that framework or produce a degraded sky.

The fix that lets us avoid all of that complexity at runtime: **precompute the integral once at build time** and store the result in a small 2D LUT. At runtime the shader is just two texture samples and a tone-map. ~50 ALU ops per pixel. Trivially fast.

## The LUT

The atmosphere LUT (`public/textures/atmosphere-lut.png`, 256 × 64 RGBA, ~64 KB) is generated by `tools/buildAtmosphereLut.ts` (see [`data/11-earth-textures.md`](../data/11-earth-textures.md) for build details).

Encoding:
- **U axis (256 texels)** — sun elevation angle, mapped from -10° (well below horizon, deep night) through 0° (horizon, peak sunset) to +90° (zenith, daylight). Non-linear mapping concentrates resolution near the horizon where the gradient changes fastest.
- **V axis (64 texels)** — view elevation angle, from -10° (looking slightly down) through 0° (horizon) to +90° (zenith).
- **RGB** — the in-scattered atmospheric color, tone-mapped to display sRGB.
- **A** — the optical-depth-derived "sky brightness" — used by the star renderer to fade stars in/out as the sky darkens.

The LUT is sampled with bilinear filtering. The shader does not need to know the underlying physics; it just looks up the right texel.

### Why not a per-frame CPU computation

We could re-evaluate scattering each frame in TypeScript and upload as a uniform. We don't, for two reasons:

1. **The integration is non-trivial** (Rayleigh + Mie phase functions, vertical density profile, multiple scattering bounces). Precomputed once, looked up forever, is the standard approach.
2. **The animation is on a tightly-controlled curve** (sun elevation drops linearly from 0° to -8° over 8 seconds). The LUT covers the entire range. We just sample at the current sun elevation.

## The shader

### Vertex stage

A single full-screen triangle (no quad needed; one triangle larger than the screen). The vertex shader emits clip-space position and a view-direction vector derived from the inverse-projection.

```wgsl
struct VertexOut {
  @builtin(position) clip: vec4<f32>,
  @location(0) view_dir: vec3<f32>,
};

@vertex
fn vs_main(@builtin(vertex_index) vid: u32) -> VertexOut {
  // Single full-screen triangle covering [-1,-1] to [3,-1] to [-1,3] in NDC.
  let x = f32((vid << 1u) & 2u) * 2.0 - 1.0;
  let y = f32(vid & 2u) * 2.0 - 1.0;
  var out: VertexOut;
  out.clip = vec4(x, y, 0.0, 1.0);
  out.view_dir = (uniforms.inv_view_proj * vec4(x, y, 1.0, 1.0)).xyz;
  return out;
}
```

### Fragment stage

```wgsl
struct AtmosphereUniforms {
  inv_view_proj: mat4x4<f32>,
  sun_dir: vec3<f32>,        // unit vector pointing toward the sun
  sun_elevation_norm: f32,   // 0..1, mapped to the LUT's U axis
  ground_color: vec3<f32>,   // for the silhouette below the horizon
  exposure: f32,             // tone-mapping multiplier; 1.0 default
}

@group(0) @binding(0) var<uniform> uniforms: AtmosphereUniforms;
@group(0) @binding(1) var atmosphere_lut: texture_2d<f32>;
@group(0) @binding(2) var atmosphere_sampler: sampler;

@fragment
fn fs_main(in: VertexOut) -> @location(0) vec4<f32> {
  let view_dir = normalize(in.view_dir);
  let view_elevation = view_dir.y;  // assuming +Y is up

  // Ground plane: if the view direction is below horizon, return ground color.
  if (view_elevation < 0.0) {
    return vec4(uniforms.ground_color, 1.0);
  }

  // Sample the LUT. U = sun elevation (precomputed normalized), V = view elevation.
  let v_norm = clamp(view_elevation, 0.0, 1.0);
  let lut = textureSample(atmosphere_lut, atmosphere_sampler,
                          vec2(uniforms.sun_elevation_norm, v_norm));

  // Sun disc: a small bright spot when the view direction is near sun_dir.
  let sun_dot = dot(view_dir, uniforms.sun_dir);
  let sun_disc = smoothstep(0.99996, 0.99998, sun_dot);  // ~0.5° angular size

  let atmosphere_rgb = lut.rgb * uniforms.exposure;
  let final_rgb = atmosphere_rgb + sun_disc * vec3(2.5, 2.0, 1.5);

  return vec4(final_rgb, 1.0);
}
```

50-something ALU ops, two texture samples, no branches outside the ground silhouette early-out. Cheap.

### Sky brightness gate (consumed by star renderer)

The fourth channel of the LUT (`lut.a`) encodes "how bright the sky is" — used by the existing `starRenderer.ts` (Shell 2) to fade stars in as the sky darkens. The star renderer's fragment shader receives a `sky_brightness` uniform per frame and computes:

```wgsl
let star_alpha_mult = smoothstep(magnitude_threshold, magnitude_threshold - 1.0, sky_brightness);
```

A star of magnitude `m` fully appears when `sky_brightness < m`. So Sirius (m=-1.5) appears almost immediately; the dimmest Gaia DR3 cuts (m~6) appear only at full dark.

This is a clean separation: the atmosphere shader is the source of truth for sky brightness; the star shader consumes it; neither knows the other's internals.

## Sun motion

The Sun's elevation drops from 0° to -8° over T+0:00 → T+0:08 (the 8-second open). On the close, it rises from -8° to +5° over T+1:42 → T+1:46 (the 4-second close).

The CPU updates `uniforms.sun_elevation_norm` and `uniforms.sun_dir` each frame:

```ts
const sunElevationDeg = lerp(0, -8, beatProgress);  // for the open
const sunElevationNorm = (sunElevationDeg + 10) / 100;  // map [-10°, +90°] to [0,1]
const sunDirYaw = ...; // fixed; sun stays in roughly the same compass direction
```

The Sun does NOT pan azimuthally during the beat. It just sets. Real sunsets do drift azimuthally, but the effect is too subtle on this timescale; ignoring it costs nothing and saves a uniform.

## Earth-as-disc transition

At T+0:11, the camera lifts off the surface. The atmosphere shader still runs but its contribution fades out as the camera rises. We model this by attenuating the atmosphere's alpha contribution by `exp(-altitude / scale_height)` where `scale_height = 8 km`.

By T+0:14 the atmosphere shader contributes nothing. The frame is then dominated by:

1. The starfield (Shell 2's renderer — already running, just continues).
2. The Earth-as-sphere pass (`earthRenderer.ts`, see below).

### `earthRenderer.ts`

A simple textured sphere shader. Diffuse from `earth-blue-marble-4k.jpg`; night-side lit from `earth-night-lights-4k.jpg`; blend between them based on the dot product of the surface normal with the sun direction.

```wgsl
@fragment
fn fs_main(in: VertexOut) -> @location(0) vec4<f32> {
  let day_color = textureSample(diffuse, samp, in.uv).rgb;
  let night_color = textureSample(night_lights, samp, in.uv).rgb;
  let n_dot_l = dot(in.normal, sun_dir);
  let day_factor = smoothstep(-0.1, 0.1, n_dot_l);
  let final_rgb = mix(night_color, day_color, day_factor);
  return vec4(final_rgb, 1.0);
}
```

Negligible cost. ~0.5 ms.

The Earth sphere has a thin atmospheric rim — a separate billboard quad slightly larger than the sphere, shaded with the LUT's horizon color, alpha-falloff at the edges. ~0.3 ms.

## Performance

| Pass | Cost (typical) | Cost (worst case) |
|---|---|---|
| Atmosphere full-screen | 0.4 ms | 0.8 ms (high-DPI mobile) |
| Ground silhouette | 0.05 ms | 0.1 ms |
| Earth sphere (only T+0:14-0:22 / T+1:38-1:42) | 0.4 ms | 0.7 ms |
| Atmospheric rim | 0.2 ms | 0.4 ms |
| **Total** | **~1.0 ms** | **~2.0 ms** |

Comfortably within the 16 ms frame budget. The atmosphere pass replaces nothing — it adds about 1 ms of work for ~15 seconds of the tour total. Acceptable.

## Mobile fallback

Per [`ux/05-mobile.md`](../ux/05-mobile.md): on Tier B mobile (older Android, integrated GPUs), the atmosphere shader is replaced by a **pre-rendered video clip**. The open is rendered ahead of time on a desktop machine, encoded as a 1080p H.264 / WebM 8-second clip, and committed to `public/video/tour-open.mp4` (~2 MB). The mobile path plays that video in a `<video>` element behind the canvas; the canvas remains hidden until T+0:14 when control returns to the live renderer.

This is also recommended as a feature flag for **all** tiers, so any GPU surprise during the most important 8 seconds of the tour can be mitigated by flipping a single config value.

## Test criteria

- **Visual:** the open and close look identical to a hand-tuned reference frame at three sun elevations (sunset, civil twilight, full night).
- **Performance:** atmosphere pass < 1 ms on a 2024 Mac mini M-series; < 2 ms on a 2022 mid-range Android (Pixel 7a).
- **Correctness:** the sky color at sun elevation 0° matches the orange/red sunset palette specified in `shells/00a-earth-opening.md` (visual diff against a committed golden frame).
- **Star fade:** at sun elevation +5°, no stars are visible. At sun elevation -1°, only stars brighter than mag 1 are visible. At sun elevation -8°, all Gaia DR3 cuts are visible.
- **No banding:** the gradient transitions are smooth across the 256-texel U axis. If banding appears at the orange-to-red transition, increase LUT resolution to 512.
- **No flicker on transition:** at T+0:08 → T+0:11, when the camera tilts up and lifts off, no abrupt color changes; the gradient should already have flattened to dark blue.

## Open questions

1. **Should the LUT include Mie scattering for haze?** Pure Rayleigh gives a clean blue/orange gradient; Mie adds a haze near the horizon that some viewers expect ("layer of dust"). **Recommendation:** include Mie in the precompute; it's free at runtime since it just goes into the same LUT.
2. **Cloud layer?** A real sunset often has clouds catching the light. Adding clouds would be visually striking but is a different scope (cloud noise texture, separate render pass). **Recommendation:** skip in v1; revisit if the user feels the sunset looks "empty."
3. **Should we let the user choose latitude / time-of-year via a URL parameter?** `?tour=auto&lat=30N&date=summer-solstice` — adds personalization. **Recommendation:** no in v1; we want a single canonical opening that we control, so the share clip is consistent.
4. **Color-grade the open to match the rest of the tour?** The atmosphere LUT is physically motivated; the rest of the tour uses an observatory-readout color palette. There is a tonal seam at T+0:14. **Recommendation:** apply a slight desaturation (~85%) and contrast bump to the atmosphere output during the lift-off frames T+0:08-0:14 so the visual transition reads as "moving from photographic to clinical" rather than as a hard cut.
