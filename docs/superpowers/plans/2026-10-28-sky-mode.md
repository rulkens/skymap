# Sky mode (Stellarium-style), the feature — plan

> **Spec.** [`specs/2026-10-28-sky-mode-design.md`](../specs/2026-10-28-sky-mode-design.md) §4–§7.
> **Builds on.** #949 (`camera.lens`, the `fov` clip channel) and #952 (prep: segment quads behind
> the eye, the ~0.5 m near floor). This branch, `sky-mode`, is stacked on both until they merge.
> **Gate.** `npm run typecheck`, `npm test`, CI's build, `npm run perf` at a sky pose at 60° and
> 0.5° before/after (spec §7), and the spec's eye checks. Execution follows the lean SDD protocol
> (`conventions/sdd-execution.md`).

## Contract amendments found while planning (decisions, review them)

The spec's §4 assumed two things the rung contract does not do. Both close with small,
behaviour-preserving growth (T1), not with a tag branch outside `rungs/`:

1. **The wheel's lens write.** `RungRow.step` returns only a pose, and the lens is `camera.lens`,
   which sits beside `base` (#949). A step may now also return `lens`. `replayInput` emits
   `setLens` for it and threads the new lens into the next step's `ctx.fovYRad`, so several notches
   in one drain compound.
2. **The zoom-out exit.** `ClimbRow.release(framed, ctx)` never sees rung memory, but the exit push
   lives there (`MemOf.sky`). `release` gains the rung's memory, and body/site ignore it. The fold
   (`stepRung`) stays the one place a regime edge happens, so no step result ever changes a frame.

## Contract

```ts
// src/@types/camera/ — one type per file
type PoseFrame = … | { readonly sky: SceneBodyId };
type RungKind = 'absolute' | 'body' | 'site' | 'sky';
type SkyPose = {
  readonly lonRad: number; readonly latRad: number;          // body-fixed; height derived, never stored
  readonly azimuthRad: number; readonly altitudeRad: number; // site ENU, az from north through east
};
type SkyMemory = { readonly exitPushPx: number; readonly lastPushMs: number | null };
// PoseOf.sky = SkyPose; FrameOf.sky = { sky: SceneBodyId }; MemOf.sky = SkyMemory; ParentOf.sky = 'body'

RungRow.step(...) → { pose; memory; tilt; lens?: number }       // T1
ClimbRow.release(framed, ctx, memory: MemOf[K]): boolean         // T1

// src/data/camera/
SKY_EYE_HEIGHT_M = 1.7; LENS_MIN_DEG = 0.5; LENS_MAX_DEG = 120;
SKY_EXIT_PUSH_PX; SKY_EXIT_PUSH_DECAY_MS; SKY_EXIT_ALTITUDE_M      // tuned by eye (spec §9)

// state
type TakeoverSource = … | { kind: 'sky'; body: SceneBodyId };
type SkyTarget = 'view' | { body: SceneBodyId; lonDeg: number; latDeg: number };
enterSky(SkyTarget)                         // saga action: starts or re-aims the takeover
skyEntry(SkyTarget) → skyEntered(SkyPose & { body }) | skyEntryMissed   // camera action, engine-resolved
```

## Tasks

### T1. Rung contract growth (behaviour-preserving, one commit)

- **Step lens.** `step` may return `lens`. `replayInput` emits `setLens` for it and threads it into
  the following steps' `ctx`.
- **Release memory.** `release` takes the rung memory. `stepRung` and `projectFramePose` pass the
  runtime's gesture memory for the current frame key.
- **Gate.** Golden traces stay byte-identical; no row returns a lens yet.
- **Tests.**
  - `replayInput.test.ts`: `a step's lens is emitted as setLens and seen by the next step`.
  - `stepRung.test.ts`: `release reads the rung memory it is handed`.

### T2. The sky rung (one commit, TDD)

- **Rows and types.**
  - `rungs/skyRung.ts` is a `ClimbRow<'sky'>`, plus its key in `CAMERA_RUNGS`.
  - `rungKindOf` gains the `'sky'` branch and stays the one spelling reader
    (`oneTagReader.test.ts`).
- **The row's cells.**
  - **`host`:** the frame's body.
  - **`toParent`:** a `BodyFixedPose` with the eye at `datum + ctx.terrainHeightAt + SKY_EYE_HEIGHT_M`
    and the basis turned by az/alt (reuse `siteEyeFrame` and `lookedSurfacePose`'s math).
  - **`fromParent`:** the inverse. It reads lon/lat from the eye's radial and az/alt from the
    basis, clamped.
  - **`step`, drag:** 1:1 at `ctx.fovYRad / viewportHeightPx` rad/px; altitude clamps to ±π/2 and
    azimuth wraps.
  - **`step`, zoom:** multiplicative on `ctx.fovYRad`, clamped to [`LENS_MIN_DEG`, `LENS_MAX_DEG`],
    and returned as `lens`. At the widest stop the wheel-out pixels add to `exitPushPx`, and
    wheel-in, drag or `SKY_EXIT_PUSH_DECAY_MS` of rest clears it.
  - **`nudge`:** `look` turns the view, `zoom` is the lens, and `orbit`/`roll` are ignored.
  - **`engage`:** always null (spec D3).
  - **`release`:** the push is past `SKY_EXIT_PUSH_PX`, or the focus left the host.
- **Channels.** `target: [lon, lat, 0]`, `yaw: az`, `pitch: alt`, `distance: 0`. The URL pose
  codec gets the tag letter `k`.
- **Tests:** spec §7's `skyRung.test.ts` list verbatim, plus `encodeFramedPose`'s sky round-trip.

### T3. Takeover, entry and exit (one commit)

- **Takeover.**
  - `TakeoverSource` gains `sky`.
  - A `skyBodySaga` runs **outside** `withSceneSnapshotSaga` (spec D2). It captures `camera.base`
    at entry and commits it back on `exitTakeover`.
  - Tours, exhibits and clips preempt it the usual way.
- **Entry, resolved in the engine.**
  - `skyEntry` is drained where `heightAt` lives. `'view'` is `terrainPickAt` at the viewport
    centre, falling back to the datum sphere hit.
  - The arrival is a body-arm tween to the floor above the site that keeps the heading, then a
    commit of the sky pose (altitude 15°, the current lens).
  - It dispatches `skyEntered` or `skyEntryMissed`. On a miss the takeover ends with the status
    "Point the view at the ground first."
- **Exit by zoom-out.** A release to `body` (T2) at `SKY_EXIT_ALTITUDE_M` above the site, looking
  down, ends the takeover without a restore.
- **Tests:** spec §7's `skyTakeover.test.ts` list verbatim.

### T4. The `skyGrids` Layer (two commits: geometry, then render)

- **Geometry (pure, TDD).** One function per `utils/` file:
  - `greatCirclePolyline`: unit directions at ≤ 1° steps.
  - `siteEnuBasis(lonRad, latRad, orientation)`.
  - `hostEquatorialBasis(orientation, orbitPole)`: the pole is the orientation's third column; RA
    zero is the vernal equinox, the node of the equator on the orbit plane (spec §5, of date since
    #947).
  - The grid line sets for alt-az (10°/15°), equatorial (15° RA, 10° Dec), the celestial equator,
    the ecliptic (`ECLIPTIC_FRAME`) and the meridian.
- **Render.**
  - A static vertex buffer of directions, drawn as points at infinity through `expandSegmentQuad`
    and `edgeBandMask`, with one `mat3` per moving grid.
  - The pass sits in `POST_FOREGROUND` beside `orbit-trails`, sampling `foreground:0` depth (hidden
    where finite).
  - The daylight dim is a CPU scalar from the Sun's altitude at the site.
  - Visibility items: `cardinals`, `altAz`, `equatorial`, `ecliptic`, `meridian`. They draw only
    when the rung is `sky`.
- **Cardinals.** A new `CaptionKind` `'cardinal'` ranked above constellation names, at fixed pixel
  size, altitude +1°, drawn over terrain.
- **Tests:**
  - spec §7's `skyGridBasis.test.ts` list (with the #947 names);
  - `greatCirclePolyline` closes and keeps every step ≤ 1°;
  - a uniform/vertex layout parity test, per `RENDERER.md`.

### T5. UI (one commit)

- **Palette.**
  - `ScoredRow` and `PaletteAction` gain `sky`, and `remoteCommands` parses it.
  - The rows: "Sky from here" when the host has terrain, "Sky from <place>" beside each
    `EARTH_PLACES` match, and "Sky from 52.37° N 4.89° E" for a typed `lat, lon` query
    (`parseLatLonQuery`, pure, TDD).
- **Keys.** `s` enters, `g` toggles the five grid items; both are added to `NavigationPanel`'s list.
- **Readout and settings.**
  - The readout (place, lat/lon, az/alt of the view centre, field of view) replaces the ScaleBar in
    sky mode, through `engineSlice`.
  - A "Sky grids" SettingsPanel section; toggles go in `PERSISTED_VALUES`.
- **URL.** The appended `sky=` hash row `<body>,<lat>,<lon>,<az>,<alt>,<fov>`, written on enter,
  settle and exit only.
- **Tests:** spec §7's `rankPaletteMatches.test.ts` pair, `parseLatLonQuery` cases, and the ui-ux
  interaction tests.

### T6. Measure and look

- **Perf.** `npm run perf` at a sky pose at 60° and 0.5°. If 0.5° regresses, `LENS_MIN_DEG` rises
  and the cause is backlogged.
- **Eye checks.** Amsterdam at night with all grids, the same at noon, Jezero, and the zoom-out exit
  mid-tween. Each goes to the user as a dash check.
- **Wrap-up.** `/feature-done`, with the deletion audit.
