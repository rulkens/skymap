This feature is split into four independently shippable sub-plans. Read them
in dependency order; each one produces working software that the user can
review before the next plan starts.

The original 2900-line monolith (`2026-05-05-cf4-flow-field.md`) was split
on 2026-05-05 because per the writing-plans skill, "If the spec covers
multiple independent subsystems, it should have been broken into sub-project
specs."

## Why CF4

Cosmicflows-4 (Tully+ 2023) reconstructs the local peculiar-velocity field
from ~56k galaxy distances. Watershed segmentation of that field carves the
nearby universe into **basins of attraction** — Laniakea, Great Attractor,
Perseus-Pisces, Shapley, Coma, Hercules. The dataset we consume is
[laniakea](https://github.com/) by C. Dupuy: a Python pipeline that has
already done the watershed, basin assignment, and RK4 streamline integration
and ships the results as CSVs. Our job is to convert those CSVs into compact
binary assets and render them with the existing skymap WebGPU machinery.

## Architecture decision

We chose **Option A: ship laniakea CSVs into `data/raw/cf4/`** instead of
shelling out to Python at build time. Rationale:

- Total CSV size is ~107 MB uncompressed but compresses well; the
  derived `.bin` artefacts are ~12 MB total (galaxies + streamlines).
- Laniakea's pipeline is non-trivial (FITS conversion, watershed, RK4) and
  takes 30-60 minutes; baking the result into committed assets means
  contributors don't need Python set up to build skymap.
- Updates are rare (CF4 is a published catalogue, not a streaming feed), so
  the asset re-pin cadence is low.
- We do NOT commit the 90 MB streamlines CSV to git; instead `data/raw/cf4/`
  has a README pointing to the laniakea repo + commit hash, and
  `npm run build-cf4` reads files from a path the user supplies.

See plan 01 for the full pinning + on-disk-layout details.

## Stop-anywhere guarantees

Each plan finishes with working, demo-able software:

- **After 01:** the binaries exist on disk and `decodeCf4Galaxies` /
  `decodeCf4Streamlines` round-trip them in a unit test. Nothing renders
  yet, but the build is verifiable.
- **After 02:** ~56k CF4 galaxies render as monochrome dots in the correct
  SG positions. Users see the local-universe distance-measured sample
  superimposed on the SDSS+2MRS+GLADE point cloud. No streamlines yet.
- **After 03:** streamlines render in monochrome. Users see the flow field
  arcing toward attractors. Basin colours still uniform (e.g. cyan).
- **After 04:** full Tully-style visualisation — galaxies and streamlines
  coloured by basin, with toggles to mix-and-match overlays.
