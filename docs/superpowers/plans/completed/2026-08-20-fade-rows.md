### D2 — `FADE_ROW` is **derived**. `VISIBILITY_ACTION_ROW`'s row grows a `writes` field

**Verdict: DERIVE.** This is the one place in the family where a derivation is
both available and honest.

The pair is a true inverse: each of the 15 `FADE_ROW` entries is
`creator.type → key`, and each of the 15 non-empty `VISIBILITY_ACTION_ROW` rows
calls exactly one creator. The creator is currently _buried inside a closure_,
which is the only reason the inverse has to be hand-written in a second file.
Lift it to row data and the inverse falls out:

```ts
// src/services/animation/visibilityActionRow.ts  (contract)
type VisibilityActionRow = {
  /** The settings creator this layer writes; `null` for registration-only layers. */
  readonly writes: { readonly type: string } | null;
  readonly actions: (on: boolean, settings: EngineSettingsState) => readonly Action[];
};

export const VISIBILITY_ACTION_ROW: Record<VisibilityLayerKey, VisibilityActionRow>;

/** Derived inverse: action type → the layer it drives. Was hand-kept in watchFadesSaga.ts. */
export const FADE_ROW: Partial<Record<string, VisibilityLayerKey>>;
```

`writes` is `| null`, never optional: a `Record` cannot be satisfied by
omission, so a new key must state its stance — the same discipline
`fadeIdToVisibilityKey`'s `satisfies Record<…>` uses. It is not the per-row
exception #10 bans: 15 of 18 rows carry it, so it names a capability the family
shares.

**Rejected — deriving `actions` from `writes` too.** It needs a payload
taxonomy: 8 rows are `creator(on)`, 6 are
`Object.keys(settings.X.items).map(id => creator({ id, enabled: on }))`, and
`volumeField` is `writeVolumeField({ id, patch: { enabled: on } })`. That is a
3-arm tagged union over 15 rows to save ~20 lines. Per #10 the misfit is in the
_contract_ — `writeVolumeField`'s patch shape versus the other creators' flat
shape — and normalizing that is a settings-slice change, not a behaviour-neutral
rung. Not attempted; recorded so the next reader does not re-derive it.

**Rejected — deriving `writes` from `actions` at runtime**
(`actions(true, settings)[0]?.type`). Per-item factories return `[]` over an
empty settings record, so the derivation is seeded-state-dependent. A silently
missing `FADE_ROW` entry is exactly the failure this rung exists to remove.

**Layering consequence, checked.** `watchFadesSaga.ts` gains an import from
`src/services/animation/` — today `src/store/` imports nothing from
`src/services/` (`grep -rn "from '.*services/" src/store` is empty). Accepted:
`visibilityActionRow.ts` imports only `@types` + `settingsSlice`
(`:44-68`) — no engine, no GPU — so the saga's stated constraint ("keeps the
store layer free of engine imports", `watchFadesSaga.ts:20-22`) is preserved
verbatim, and the reverse edge already exists (`applySceneEffect.ts:69` imports
`store/types`). No cycle: `settingsSlice` imports nothing from `store/`. The
adjacent precedent is already in the tree: `src/state/tour/computeSceneEntering.ts:41-42`
imports both `visibilityActionRow` and `scopedVisibilityActions` from
`src/services/animation/`. That is `src/state/`, not `src/store/` — a
neighbouring layer, not the same edge — so it is corroboration, not proof; the
argument above stands on its own.

**Call-site consequence, enumerated.** `VISIBILITY_ACTION_ROW[key]` stops being
callable, so every caller gains `.actions`. There are **three files / six call
expressions**: `applySceneEffect.ts:92,112`, `scopedVisibilityActions.ts:41,42,43`,
and `src/state/tour/computeSceneEntering.ts:57`. `npm run typecheck` is the gate
(the last one is easy to miss by grepping only `src/services`).

### D3 — `FADE_LAYERS` and `VISIBILITY_ACTION_ROW` do **not** merge

**Verdict: JUSTIFY.** Both are keyed by `VisibilityLayerKey`, and their
registration-only subsets coincide exactly, which invites a merge. Two facts
refuse it:

1. **Layering.** `FADE_LAYERS` rows close over `EngineState` — `state.gpu.
galaxyPointRenderer`, `maybeLazyLoadDebugVolume`, `SOURCE_REGISTRY`
   (`fadeLayers.ts:226,242,290,306-315`). Merging would drag the engine into
   the store's saga graph, breaking the one constraint D2 just preserved.
2. **Item domains differ.** `FADE_LAYERS.survey.expand` yields the compile-time
   `GALAXY_CATALOG_IDS`; `VISIBILITY_ACTION_ROW.survey` enumerates
   `Object.keys(settings.galaxyCatalogs.items)` at dispatch time. A merged row
   would have to pick one, changing behaviour for whichever loses.

The coincidence they _do_ share — `row.intent === undefined` ⟺
`row.writes === null` — is pinned by one structural test (T4) instead of a
merge. That test also **replaces** a hand-listed key restatement that has
already drifted: `fadeLayers.test.ts:380-392` lists 11 intent keys of the
actual 15 (`constellations`, `starCatalogLabel`, `bodyLabel`,
`zoneOfAvoidance` missing) — a `testing.md` registry restatement that silently
stopped covering four rows. Net: stronger coverage, fewer lines.

### D4 — `fadeIdToVisibilityKey` is **not** derived from `FADE_LAYERS.handle()`

**Verdict: JUSTIFY — refuted by a concrete counterexample.** `FADE_LAYERS`
carries the forward map (`key` → `handle()`), so the inverse looks derivable by
walking it. It is not: `VISIBILITY_KEY_BY_KIND.overlay` is deliberately
`undefined` (`fadeIdToVisibilityKey.ts:87-92`) while `FADE_LAYERS` _does_ map
`{kind:'overlay',id}` to `proceduralDisks`/`texturedDisks`
(`fadeLayers.ts:106-119`). The hand table's divergence from the forward map is
the whole point of it: `:87-92` is a _stance_ — "no clip cue addresses the
always-on disk overlays" — and a derived inverse would silently overwrite it.

Precisely what that costs: **nothing today**, because §0.1 establishes those two
handles have zero readers, so no `{kind:'overlay'}` `FadeId` ever reaches
`resolveLayerOpacity`. The cost is _armed_, not paid — the moment a reader
appears (a disk overlay wired up in some later rung), a derived inverse starts
applying a clip factor to an always-on overlay, and nobody reviewing that rung
would be looking here. Trading a recorded stance for two table rows is the wrong
side of that trade even at zero present cost.

### D7 — the canonical-path contract changes shape: `resolveLayerOpacity(state, ctx, h)`

**This is the #10 move: the row didn't fit, so the contract changed — for all
rows, not one.**

Today every canonical call spells out five arguments, four of which are always
the same two ambient bags (`filamentsLayer.ts:112-118`,
`orbitTrailsLayer.ts:233-239`, `volumeLiveness.ts:93-99`,
`zoneOfAvoidanceLiveness.ts:26-32` — 7 formatted lines apiece). That is _why_
the raw one-liner keeps winning: the canonical path costs 6 more lines at every
site. Fix the cost, and the bypass stops being the path of least resistance.

```ts
// src/services/engine/presentation/focusRecession.ts  (contract)
export function resolveLayerOpacity(
  state: Pick<EngineState, 'subsystems'>,
  ctx: Pick<ReadyFrameContext, 'focusBlend' | 'nowMs'>,
  h: FadeId,
): number;
```

`clip` stops being optional — `state.subsystems.clipPlayer` is always present
(every existing caller already passes it unconditionally), which also deletes
the `clip === undefined ? 1 : …` arm at `:174`. `focusRecession` and
`recessionTargetFor` stay pure and unchanged; only the composition sugar takes
the bags, which is what it is for (`focusRecession.ts:154-166`).

`Pick<…>` rather than the full types keeps the function testable with two small
literals and keeps the dependency honest.

### D8 — seven raw draw-alpha sites become canonical; nine gate sites stay raw, by a stated rule

**The rule** (recorded once, in decision #18 — see S7's budget note in D15 for
why it does _not_ go in `focusRecession.ts`'s header). It classifies by **what
the site's answer controls**, not by the shape of the expression:

> `opacityOf` is the layer's **intent** fade — toggle, load-in, tier swap.
> Recession and clip are **presentation** factors: they dim a layer that is
> still fully enabled and fully resident. So:
>
> 1. **A value the viewer sees** — a drawn alpha, and any `> 0` / `!== 0` skip
>    derived from _that same drawn value_ — resolves through
>    `resolveLayerOpacity`.
> 2. **A value that decides whether the layer's work happens at all** — does the
>    pass run, does data stay resident, does the fade-out tail keep drawing,
>    does this source claim a hit — reads `opacityOf` raw. Keying these on
>    recession or clip would unload, stall, or unclick a layer that a focus tween
>    or a clip cue merely _dimmed_.
> 3. **Per-instance producers** compose the three factors by hand, because they
>    apply a focused-instance exemption _between_ them (D10).

The three buckets partition all 21 raw `opacityOf` sites: 7 + 9 + 5.

**Migrate — 7 sites, one per file:**

| site                                                              | id                      | recession   |
| ----------------------------------------------------------------- | ----------------------- | ----------- |
| `milkyWayCloudLiveness.ts:58`                                     | `{milkyWay}`            | `undefined` |
| `produceMilkyWayLabel.ts:69` (the **draw** half only — see below) | `{labelLayer,milkyWay}` | `undefined` |
| `galaxyPointSpritesLayer.ts:144`                                  | `{galaxyCatalog,id}`    | `undefined` |
| `constellationsLayer.ts:130`                                      | `{constellations}`      | `undefined` |
| `foregroundLabelsLayer.ts:529`                                    | `{constellations}`      | `undefined` |
| `flowFieldLayer.ts:65`                                            | `{flow}`                | `undefined` |
| `volumeLiveness.ts:114`                                           | `{volumeField,id}`      | `undefined` |

**Stay raw — 9 sites:** `filamentsLayer.ts:89`, `orbitTrailsLayer.ts:184`,
`flowFieldLayer.ts:49`, `constellationsLayer.ts:113` (pass-runs gates);
`volumeLiveness.ts:87` (master liveness gate — returns `null`, i.e. no volume

**Two sites the rule has to be right about, ruled explicitly:**

- **`produceMilkyWayLabel.ts:69` splits in two.** One binding serves both the
  gate at `:76` (`!labelEnabled && layerOpacity === 0` → emit nothing) and the
  drawn alpha at `:106` (`distAlpha × deepZoomFade × layerOpacity`). Those fall
  in different buckets, so the site **legitimately grows by one line**: a raw
  binding for the gate, a resolved binding for the alpha. Merging them either
  way is wrong — resolve the gate and a clip fade to 0 truncates a disabled
  label's fade-out tail; leave the alpha raw and beat D's `milkyWayLabel` cue

- **`galaxyPointSpritesLayer.ts:191` STAYS RAW.** It is the `drawPick` pick

  _"Picking follows **intent**, not pixels"_ (`deriveSourceMasks.ts:25-27`) —

### D11 — `syncVisibilityFadeItem` loses its `animate` parameter (discharges #15 D8)

**Verdict: DELETE — by narrowing the contract, not by deleting a line.** #15 D8
handed rung 7 the production-dead `animate: false` wake arm

export function syncVisibilityFadeItem(

Behaviour-neutrality is explicit, not inferred: the entry still delegates to

passes `{ ...opts, animate: true }` — the literal the sole caller passes today.

`syncVisibilityFades` (the batch bridge) keeps `animate` — it has real
snap-path callers, and its own "Why the wake is asymmetric" section
(`:116-128`) documents a path that survives; only the **mirror** comment at
