# Sky rung, clip-only slice — plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development under the lean
> protocol (`conventions/sdd-execution.md`). Steps use checkbox (`- [ ]`) syntax.

**Goal:** a clip leg tagged `{ sky: SPOT }` stands the eye 1.7 m above the live terrain at a lon/lat
and looks by compass azimuth and altitude, horizon level, while the body turns under the clock.

**Architecture:** one new rung row (`skyRung`, a `ClimbRow<'sky'>` under `body`) plus its type keys,
two pure fold helpers beside the site's, and the URL tag letter `k`. Every dispatch site already
goes through the row table (#1019), so nothing outside `rungs/`, the type maps and the URL codec
learns the new kind.

**Spec:** [`specs/2026-11-03-sky-rung-slice-design.md`](../../specs/completed/2026-11-03-sky-rung-slice-design.md)
§4–§6. Its §3.3 prep landed as #1019.

**Branch:** `sky-rung`, off main at `22430550f`.

## Global Constraints

- The frame tag is `{ sky: SkySpot }`: one key, the kind. The place lives in the tag and never in the pose (R2).
- Eye height `SKY_EYE_HEIGHT_M = 1.7` m above `datum + terrainHeightAt` along the sphere radial (R3).
- No `'sky' in …` test outside `rungs/`: `oneTagReader.test.ts` is the ratchet. A site that
  narrows on frame kind goes through `rowFor`, `isSkyArm` or `isWorldArm`.
- `step` and `nudge` decline: they return `framed.pose` **by reference**. `engage` is always `null`.
- Roll is identically zero. Azimuth runs from north through east, and altitude lies in [−π/2, π/2].
- URL numbers go through `String(n)`, never `toFixed`.

## Decisions taken at planning (review them)

1. **The basis is `canonicalBasisAt(spotEnu, azimuthRad, π/2 + altitudeRad)`.** That function
   (`src/utils/camera/canonicalBasisAt.ts`) is already roll-free, and its horizontal axis comes
   from the azimuth alone. So looking straight up or down keeps a defined azimuth with no
   special case. The spec's "reuse `lookedSurfacePose`'s math" is replaced by this call, which
   needs no starting basis to turn from.
2. **Eye checks 1–3 use `#pose=k,…` links instead of a debug clip.** The `k` letter makes the
   standing view a deep link, so no clip registry entry is needed. **Check 4 (the rise) moves to
   the tour PR.** The tour's opening beat is that clip, and a debug clip here would be deleted
   there. The `sky → body` unit test (Task 2) guards the rise in this PR.
3. **The anchor is the spot's ground point.** The body arm `toParent` returns is anchored at the
   ground point (`datum + terrain`), with `eyeRelAnchorM = SKY_EYE_HEIGHT_M · localUp`. This
   mirrors `sitePoseToBodyArm`, which anchors at the site so the stored magnitudes stay at human
   scale.

## Review Focus

1. **Straight up or down.** At altitude ±π/2 the forward vector has no horizontal part. The
   azimuth must still round-trip, read off screen-up (Task 1, round-trip test).
2. **A spot at a pole.** At latitude ±π/2, `siteEyeFrame`'s degenerate ENU branch must give a
   finite basis that round-trips (Task 1).
3. **An azimuth outside (−π, π].** An authored azimuth must produce the same view as its wrapped
   value, and `fromParent` returns it wrapped (Task 1).
4. **The way in.** An absolute → sky leg must open looking where the clip's start looked. This
   is the tour's entry path (Task 2).
5. **A landed sky pose ignores drag and wheel.** That is accepted for this slice. The decline
   must return the same object, or the drain commits a "moved" pose every notch (Task 1).

**Contract:**

```ts
// src/@types/camera/SkySpot.d.ts
export type SkySpot = {
  readonly body: SceneBodyId;
  readonly lonRad: number; // east-positive, IAU body-fixed (surfacePointBodyFixed's convention)
  readonly latRad: number; // geodetic WGS84 laid straight onto the sphere, as SurfaceFixedSite.latDeg
};
// src/@types/camera/SkyPose.d.ts
export type SkyPose = { readonly azimuthRad: number; readonly altitudeRad: number };

// type maps
RungKind = 'absolute' | 'body' | 'site' | 'sky';
FrameOf.sky = { readonly sky: SkySpot };  PoseOf.sky = SkyPose;
MemOf.sky = null;                         ParentOf.sky = 'body';

// src/data/camera/skyEyeHeightM.ts
export const SKY_EYE_HEIGHT_M = 1.7;

// src/utils/camera/skyPoseToBodyArm.ts — groundRadiusM = host datum + terrainHeightAt(spot dir)
export function skyPoseToBodyArm(pose: SkyPose, spot: SkySpot, groundRadiusM: number): BodyFixedPose;
// src/utils/camera/skyPoseFromBodyArm.ts — the eye is dropped: the tag fixes it
export function skyPoseFromBodyArm(arm: BodyFixedPose, spot: SkySpot): SkyPose;

// src/services/engine/camera/rungs/isSkyArm.ts
export function isSkyArm(framed: FramedCameraPose): framed is FramedPose<'sky'>;
// src/services/engine/camera/rungs/skyRung.ts
export const skyRung: ClimbRow<'sky'>;
```

**Row cells** (`siteRung.ts` is the pattern to follow):

| Cell | Behaviour |
| --- | --- |
| `kind` / `parent` / `emptyMemory` | `'sky'` / `'body'` / `null` |
| `identity` | `` `${body},${String(lonRad)},${String(latRad)}` `` |
| `host` | `hostOf({ body: frame.sky.body }, ctx)` |
| `channels.encode` | `refoldTo` the world pose into the frame, assert `isSkyArm`, then `{ target: [0,0,0], yaw: azimuthRad, pitch: altitudeRad, distance: 0 }` |
| `channels.decode` | `{ azimuthRad: yaw, altitudeRad: pitch }` as authored, unclamped |
| `toParent` | `{ frame: { body }, pose: skyPoseToBodyArm(pose, spot, host.radiusM + ctx.terrainHeightAt(body, dir)) }`, with `dir` the spot's unit radial |
| `fromParent` | `{ frame, pose: skyPoseFromBodyArm(parent.pose, frame.sky) }` |
| `step` / `nudge` | `{ pose: framed.pose, memory, tilt }` / `{ pose: framed.pose, tilt }`, with `pose` passed by reference |
| `engage` | `null` |
| `release` | `!focusInSubtree(ctx.focusBodyId, frame.sky.body)` |

**The fold math:**

- `skyPoseToBodyArm`:
  - the ENU is `siteEyeFrame(dir)`;
  - the anchor is `dir · groundRadiusM`;
  - `eyeRelAnchorM = SKY_EYE_HEIGHT_M · localUp`;
  - `basisLocal = canonicalBasisAt(enu, azimuthRad, π/2 + altitudeRad)`.
- `skyPoseFromBodyArm`:
  - Read the view in the spot's ENU (`siteEyeFrame(dir)`): `altitude = asin(clamp(forward · localUp, −1, 1))`.
  - The azimuth comes from `refAzimuthOf(localUp, forward, up, east, north)`, except when
    `forward · localUp > 1 − ε`. There it reads `atan2` of `−up`'s horizontal part, because at
    tilt π, `canonicalBasisAt`'s up is minus the horizontal azimuth axis.
  - `refAzimuthOf` already covers the nadir side. The value of ε is the builder's call.
