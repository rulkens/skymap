# Shot prep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development under
> [`sdd-execution.md`](../conventions/sdd-execution.md) to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the three joints `npm run shot` needs — a real "frame was drawn" signal, a generic page
hook, and shared build/preview server helpers — without changing what `perf`, `record-*` or
`capture-featured` do.

**Architecture:** `renderScheduler.nextFrame()` is the one drawn-frame primitive, reached by sagas
through `SagaContext` and by hooks through `EngineHandle`. `window.__skymap` is an always-installed base
hook carrying the members every Playwright tool shares; the perf and recorder hooks keep only their own.
The recorder's build/preview functions move to `tools/utils/serve/`.

**Tech Stack:** TypeScript, Redux Toolkit + redux-saga, Vite, Vitest, Playwright.

**Spec:** [`docs/superpowers/specs/2026-10-05-npm-run-shot-design.md`](../specs/2026-10-05-npm-run-shot-design.md),
section "Ground preparation". PR: #842.

## Global Constraints

- `type` aliases only; one type per file under `@types/`, one function per file under `utils/`.
- Move or extract TS with `npm run move-files` / `npm run refactor` (see
  `.claude/skills/refactor/SKILL.md`), never `git mv` plus hand-edited imports.
- Comments explain why, never what; module header ≤ 10 lines.
- No behaviour change for `perf`, `record-tour`, `record-clip`, `capture-featured`.
- `nextFrame()` has no timeout and no rejection path.

## Review Focus

- **A frame that never comes.** `nextFrame()` on a destroyed scheduler or a hidden tab stays pending;
  nothing in this PR may await it on a path that must finish (engine teardown, saga cancellation).
- **Hook install order.** Tools wait on `window.__skymap` and then read `__skymapPerf` /
  `__skymapRecorder` at once; the base hook must be the last of the three to appear.
- **Capture pose without the perf hook.** `applyPose` used the perf hook's `setPose`, which also set
  auto-rotate; the replacement must leave a still camera at the exact pose.
- **`ready` under `?cinema`.** The recorder's virtual-time mode must still see `ready` resolve.
- **Tests that build the hooks by hand.** `installPerfHook.test.ts` and `installRecorderHook.test.ts`
  assert on members that move.

### Task 1: `nextFrame()` on the render scheduler

**Files:** `src/@types/engine/subsystems/RenderScheduler.d.ts` (modify),
`src/services/engine/subsystems/renderScheduler.ts` (modify),
`tests/services/engine/subsystems/renderScheduler.test.ts` (modify)

**Signature:** `nextFrame(): Promise<void>` on `RenderScheduler`.

**Behaviour:** requests a render (coalescing with one already queued) and resolves after the next
`onFrame` call has returned. Callers that arrive before that frame share it. A call made from inside
`onFrame` waits for the following frame. Pending promises are dropped, not settled, on `destroy()`.

- [x] Add the test `nextFrame resolves only after onFrame has run`: call `nextFrame()`, assert the
      promise is unsettled, pop the fake rAF callback, assert `onFrame` ran before the promise resolved.
- [x] Add the test `nextFrame requests a render when none is queued`: with nothing scheduled, assert
      exactly one rAF is queued after the call.
- [x] Add the test `concurrent nextFrame callers share one frame`: two calls, one rAF queued, both
      resolve after a single tick.
- [x] Add the test `nextFrame called inside onFrame waits for the following frame`: an `onFrame` that
      calls `nextFrame()` leaves that promise unsettled after its own tick and resolved after the next.
- [x] Implement in `renderScheduler.ts` beside `tick` (`renderScheduler.ts:71-78`).
- [x] `npm test -- renderScheduler` passes. Commit.

### Task 3: The `window.__skymap` base hook

**review: yes** (Redux state)

**Files:** `src/@types/automation/SkymapHook.d.ts` (create), `src/@types/automation/SkymapWindow.d.ts`
(create), `src/state/automation/installSkymapHook.ts` (create), `src/hooks/useEngine.ts` (modify, `:87`),
`vite.config.ts` (modify), the Vitest config if it does not inherit `define`, the ambient declarations
file that holds other build-time globals, `tests/state/automation/installSkymapHook.test.ts` (create)

**Contract:**

```ts
export type SkymapHook = {
  readonly ready: Promise<void>;
  readonly dispatch: AppDispatch;
  readonly getState: () => RootState;
  readonly nextFrame: () => Promise<void>;
  readonly projectRoot: string;
};
export type SkymapWindow = Window & { __skymap?: SkymapHook };

export function installSkymapHook(store: AppStore, engine: EngineHandle): void;
```

**Behaviour:** installs on every page load, with no URL gate. `ready` is a getter that creates
`whenStablyReady(store)` on first read and returns the same promise afterwards, so a normal visit that
never reads it creates no store subscription. `projectRoot` is the build-time constant
`__SKYMAP_PROJECT_ROOT__`, defined in `vite.config.ts` as the config file's directory.

In `useEngine`, call it **after** `installPerfHook` — tools wait on `__skymap` and then read
`__skymapPerf` immediately.

- [ ] Add the test `installs without any URL flag`.
- [ ] Add the test `ready creates no store subscription until first read`: spy on `store.subscribe`,
      install, assert zero calls; read `ready` twice, assert the same promise and one
      `whenStablyReady` call.
- [x] Add the test `nextFrame delegates to the engine handle`.
- [ ] Implement; follow `installPerfHook.ts:108-123` for the window cast.
- [ ] `npm run typecheck:fast`, `npm test -- installSkymapHook` pass. Commit.

## Definition of Done

**Deliverables**

- `RenderScheduler.nextFrame`, `SagaContext.nextFrame`, `EngineHandle.nextFrame`.
- `window.__skymap` with `ready`, `dispatch`, `getState`, `nextFrame`, `projectRoot`, on a plain URL.
- `tools/utils/serve/{ensureServeBuild,ensureDataSymlink,spawnPreviewServer}.ts`.
- `src/services/animation/afterTwoFrames.ts` no longer exists.

**Observable behaviours** (against this worktree's own dev server, by `--url`)

- Opening the app with no query flags: `window.__skymap.projectRoot` is this worktree's path, and
  `await window.__skymap.ready` resolves.
- `#focus=body-saturn` still arrives framed on Saturn and the veil lifts.
- `npm run perf -- --url <server>` completes one scenario with timings.
- `npm run capture-featured` for one body card and one exhibit card produces thumbnails that match
  the committed ones to the eye.
- `npm run record-clip -- <a short clip> --url <server>` writes a playable file.

**Out of scope**

- The `shot` tool itself, the wrong-server warning, `data/shots/`, and the CLAUDE.md convention — the
  second PR.
- Any change to `perf`'s default URL.
