# Skymap — renderer map & WebGPU landmines

Read this before touching `src/services/gpu/`, `engine`, shaders, or debugging anything about rendering.

## Renderer quick map

- **`galaxyPointRenderer.ts` + `shaders/points/*.wesl`**: instanced billboards. Vertex stride is 52 bytes / 13 slots (xyz, magnitude, colorIndex, axisRatio + sign-bit fallback flag, baked paCos/paSin, radiusMpc, vMaxWeight, schechterRatio, angularDensityWeight, baked absMag). Galaxy-static values (PA rotation, absolute magnitude) are baked at upload, not recomputed per vertex. Identity is composed on the GPU from a per-draw `SourceUniforms.sourceCode` + `@builtin(instance_index)`, NOT baked per-vertex.
- **`galaxyPickRenderer.ts`**: r32uint pick texture. The fragment writes `(sourceCode << 26) | (localIdx + PICK_SENTINEL_OFFSET)`; see `src/data/selectionEncoding.ts` for the encoding (6 bits source, 26 bits localIdx, code 63 reserved as the all-ones sentinel). Source codes are append-only (the rule lives in `sources.ts`'s docstring) — same hygiene as enum values that get persisted to .bin, applied to POI-only codes too. Read the texture with `copyTextureToBuffer` for hover/click.
- **`textureAtlas.ts` + `texturedDiskRenderer.ts` + `shaders/texturedDisks/*.wesl`**: 2048×2048 atlas of 128×128 slots for galaxy thumbnails. LRU eviction.
- **`engine/subsystems/bitmapStreamSubsystem.ts`**: the shared atlas + fetch infrastructure — LRU clock, priority-queued concurrency-limited bitmap fetcher, and the `bitmapReady`/`bitmapFailed` memoisation pair. Enqueue is idempotent (don't re-add in-flight keys — see the module header for the bug history). Catalog- and atlas-agnostic; `engine/subsystems/galaxyAtlasSubsystem.ts` configures it with the galaxy thumbnail atlas's geometry and format. Thumbnail URLs are built by `src/utils/math/{sdss,dss}ThumbnailUrl.ts`: SDSS DR18 ImgCutout (CORS-safe) for SDSS galaxies; CDS hips2fits (CORS-safe DSS proxy) for 2MRS/GLADE.
- **`engine.ts`**: per-frame loop. Per-galaxy `apparentSizePx` gates thumbnail enqueue — but the inner loop hoists `Math.tan` and pre-computes `maxCamDistForVisibility` to avoid 2.5M trig calls per frame.
- **`renderScheduler.ts` + `engine.ts` frame tail**: render-on-demand. `requestRender()` from event handlers wakes the loop; the frame body re-schedules only while `autoRotate || currentTween || hasAnyAxis || queue.inFlightCount > 0 || recent-fade` is true.
- **Earth surface virtual texture** (`utils/scene/cutSurfaceTiles.ts` + `engine/subsystems/earthTileSubsystem.ts` + `gpu/renderers/bodies/earthSurfaceTileRenderer.ts` + `gpu/resources/textureAtlas.ts` + `data/bodies/earthTileParams.ts`): detail patches streamed on top of Earth's whole-globe albedo once the screen wants more detail than the base texture (8192×4096, pyramid level 4) delivers. `cutSurfaceTiles.ts` is the pure per-frame quadtree walk — horizon reject, frustum reject, level-from-screen-density refine — that resolves BOTH products in one pass: `requests` (what to fetch) and `cut` (what to draw, each leaf's atlas residency already resolved via an injected ancestor-fallback lookup); its module header owns the algorithm, design rationale is in the plan and spec below, not restated here. `earthTileSubsystem.ts` turns the walk's fetch demand into atlas allocations and answers residency queries; `textureAtlas.ts` is the shared LRU slot atlas (also used by the galaxy thumbnail path) whose `allocate` returns `number | null`. `earthSurfaceTileRenderer.ts` draws the resolved `cut` as instanced, camera-relative curved meshes directly over the base globe pipeline (`gpu/renderers/bodies/earthRenderer.ts`, `gpu/shaders/bodies/earth/fragment.wesl`), at the same nominal radius, with a `'nearer-or-equal'` depth compare so ties resolve in its favour — the base pipeline itself carries no atlas binding or per-fragment lookup; detail is a separate draw, not a blend. Design record: [`docs/superpowers/specs/2026-07-28-earth-surface-virtual-texture.md`](superpowers/specs/2026-07-28-earth-surface-virtual-texture.md), [`docs/superpowers/plans/2026-07-29-earth-surface-virtual-texture-a-to-d.md`](superpowers/plans/2026-07-29-earth-surface-virtual-texture-a-to-d.md).
- **Body render slabs** (`utils/camera/{composeBodySlabMvp,bodySlabCamLocal}.ts` + `engine/camera/bodyRelativePose.ts` + `gpu/renderers/bodies/**` + `gpu/shaders/bodies/**`): Earth, planets, textured bodies, rings, and the cloud/atmosphere shells draw from a per-body metre-native slab, not the galaxy catalog's Mpc frame. `bodyRelativePose.ts` is the ONE seam that converts the world-space (Mpc) camera into a body's fixed metre frame (`SCALE_UNITS.MPC_TO_M`, cancelling the shared heliocentric magnitude in Mpc first); every downstream compose (`composeBodySlabMvp`, `bodySlabCamLocal`) and every renderer/shader under `bodies/` takes that already-converted `eyeRelBodyM` and never re-touches the conversion — `tests/services/engine/camera/oneMpcSeam.test.ts` gates it structurally. The older Mpc-frame primitive, `composeBodyMvp.ts`, now serves only resolved star spheres (`starSpheresLayer.ts`, `fieldStarSphereLayer.ts`), which S4 deliberately keeps out of body slabs.
- **Caption/label occlusion reads alpha, not depth** (`gpu/renderers/labels/occlusionCoverageGroup.ts`): the shared depth buffer only ever holds the LAST painter-chain row's value (each row clears its own depth, spec §7.3), so overlay fragments (labels, marker lines, selection ring) fall off against `foreground:0`'s colour-texture ALPHA instead, which accumulates under OVER compositing across chain rows while depth does not survive them. `sceneTransmittance` (`shaders/lib/sceneDepth.wesl`) returns `1 - alpha` and each overlay scales its premultiplied output by it — a factor, not a threshold, because that alpha is ALSO the `foreground:0 → hdr` composite weight: one number, one meaning. A binary `alpha > 0.5` made it mean a second thing and broke whenever a translucent producer (a dense cloud deck, Earth's descent fade) crossed the line.

## Things that have bitten us before

- **WebGPU `queue.writeBuffer` race**: interleaving `writeBuffer` with `submit` in the same frame doesn't preserve order — bake per-instance data into the vertex buffer instead of a uniform you mutate per draw.
- **Selection halo on wrong galaxy**: same root cause — selection index must come from a per-vertex attribute, not a uniform updated mid-frame.
- **CORS on DSS thumbnails**: ESO's DSS endpoint blocks browsers. Use CDS hips2fits (`https://alasky.cds.unistra.fr/hips-image-services/hips2fits`).
- **Retry storms on failed thumbnails**: the engine has BOTH a `bitmapReady` and `bitmapFailed` Set — the per-frame gate must check both. The image queue's `enqueue` is idempotent for in-flight keys.
- **`<details>` element collapsing on hover**: keep the InfoCard's outer wrapper element identical across renders so React doesn't remount and reset the `open` state.
- **iOS WebGPU is stricter than Chrome's Tint — a bad shader freezes the _whole_ canvas**: `texture_1d` sampling (`textureSampleLevel` has no 1D overload) is one example WebKit rejects but Chrome accepts. Because all HDR passes share one command encoder, an invalid pipeline makes `encoder.finish()` produce an invalid command buffer and `queue.submit()` silently drops the _entire_ frame — the loop ticks and the camera moves, but nothing ever presents. Symptom: navigation/toggles do nothing on iOS while the React UI updates fine, no thrown errors. Diagnosis: `createShaderModuleWithDevLog` (in `shaderCompileLogger.ts`) prints the real `getCompilationInfo()` error + offending line. Store 1D LUTs as N×1 `texture_2d`.
- **Earth's tile detail has no page table to keep in sync — one CPU walk resolves residency, per leaf, per frame** (`cutSurfaceTiles.ts` + `earthTileSubsystem.ts`): the same quadtree walk that decides what to fetch also resolves each visible leaf's atlas slot inline, via an ancestor-fallback lookup, so there is exactly one place a residency bug can live instead of a walk plus a GPU-side table kept in sync with it. `earthSurfaceTileRenderer.ts` then draws the resolved leaves as instanced, camera-relative curved meshes in a separate pass directly over the base globe, at the same nominal radius, with a `'nearer-or-equal'` depth compare so ties resolve in its favour.
- **A leaf with no resident tile anywhere in its ancestor chain is just absent from the cut — not a sentinel value**: `cutSurfaceTiles` drops such a leaf from `cut` entirely (its own tile, and every ancestor strictly deeper than the base level, unresident); the base globe already covers that ground and simply shows through wherever no detail patch draws over it, so every failure path (no manifest, no atlas, a 404, ground outside the cut, cold start) collapses to the same "nothing drawn" case rather than a placeholder state to maintain.
- **`textureSampleLevel`, never `textureSample`, for the Earth tile atlas read** (`earthSurfaceTile/fragment.wesl`): the atlas has a single mip level so there is no level to select, the call sidesteps WGSL's uniformity requirement for implicit derivatives, and those derivatives would be wrong anyway — the atlas uv jumps discontinuously at a slot boundary, so `dpdx` there reads garbage across the seam.
- **The Earth base level is a function of the session's TIER, not a constant** (`earthBaseLevelForTier.ts`): the three whole-globe surface textures are 2048/4096/8192 px, i.e. levels 2/3/4 on the ladder, so "the level the base already delivers" differs per tier and is derived from the tier the `earth:surface` slot actually committed (`earthSurfaceTier.ts` — the app-wide `state.tier` is only the request). A constant off the `large` ceiling made a default `medium` session stand down a level early and hand a z3 base to a z5 tile. The inversion uses an integer shift loop, never `Math.log2`: a fractional level makes every tile path a decimal and every `1 << (zWin - z)` span garbage.
- **The base level, the request floor and the bake floor are three different numbers**: the base level (above) is where `cutSurfaceTiles` roots its quadtree walk and what the engage gate compares against; the request floor is per band — `Math.max(band.min, baseLevel + 1)`, derived per session in `derivePlannerParams` (`earthTileSubsystem.ts`); the bake floor is `BAKE_MIN_LEVEL` in `tools/textures/buildEarthTiles.ts`, and the manifest is how the runtime hears about it. Rooting the walk at a band's request floor would make that band's leaves satisfy `zWin >= min` by construction, leaving the engage gate (`plan.zWin > baseLevel`) unsatisfiable against its own floor; reading the bake floor as a runtime floor would make a shallower re-bake appear to do nothing.
- **`TextureAtlas.allocate` can return `null`**: when every slot was already claimed earlier in the same frame, it refuses rather than evicts (a consumer that wants more slots than the atlas has — Earth's tile planner asks for ~107 against 64 — would otherwise evict and refetch its own working set every frame). Every caller must treat `null` as "skip this request," not retry it.
- **`copyExternalImageToTexture`'s `flipY` differs between the whole-globe upload and the atlas upload, on purpose**: whole-globe body bitmaps (`earthRenderer.ts`, `texturedBodyRenderer.ts`, `cloudShellRenderer.ts`) upload with `flipY: true` so texture v=0 lands on the image's south row, matching the mesh's south-first v. `TextureAtlas.uploadBitmap` — shared by the galaxy thumbnail atlas and Earth's tile atlas — uploads with `flipY: false`, so within a slot v=0 is the source bitmap's own top row (for an Earth tile, its north edge). Neither call is wrong; they are two different textures with two different consumers, and the reconciliation between them lives on the CPU side, in the tile-index arithmetic (`earthTileXyForUv.ts`'s `1 - v` flip) and the fragment's matching `1 - in.uv.y`, not in either upload call.
- **Full-screen ray reconstruction through an inverse MVP must use the homogeneous far-point form**: `normalize(P.xyz - cam * P.w)` for `P = invMvp * vec4(xy, 0.0, 1.0)`, never divide by `w` first. Under reversed-Z, `z = 0` is the FAR plane, so a naive `(invMvp * clip).xyz / w` divides by `w -> 0` there and every ray degenerates to the same direction (a uniform grey veil); and any finite-`z` unprojected point sits only a few near-plane distances from the camera, so `p - cam` is a metres-scale difference of otherwise unit-scale f32 vectors that shimmers as the near plane shrinks on descent. See `shell/fragment.wesl`'s `insideRayDir`.
