# Skymap — renderer map & WebGPU landmines

Read this before touching `src/services/gpu/`, `engine`, shaders, or debugging anything about rendering.

## Renderer quick map

- **Layer vs core.** A self-contained family (galaxies today; stars/structures/
  bodies/volumes follow) lives colocated under `src/layers/<name>/`
  (`layer.ts`'s `Layer` object is the only import surface — `sources/`,
  `settings/`, `load/`, `render/`, `passes/`, `sagas/`, `ui/`, `types/`), and contributes
  its passes, asset rows, fades, labels and settings section into the
  composition (`src/compositions/app.ts`); everything not yet a Layer —
  Milky Way, stars, structures, bodies, volumes, constellations, atmosphere,
  the frame executor, camera/input, targets/post, the pick program — stays
  core, under `src/services/engine/` and `src/services/gpu/`. A Layer's pass
  that no `FRAME_ORDER` line names never draws, and that's a boot-time
  failure, not a runtime one: `checkFrameOrder` cross-checks the composed
  pass set against the list once, from `startLoop`, and throws before the
  first frame renders (see the `frameOrder.ts` bullet below).
- **`galaxyPointRenderer.ts` + `shaders/points/*.wesl`**: instanced billboards. Vertex stride is 56 bytes / 14 slots (`SLOTS_PER_GALAXY_POINT`, `galaxyPointVertexLayout.ts`) — xyz, magnitude, colorIndex, axisRatio + sign-bit fallback flag, baked paCos/paSin, radiusMpc, vMaxWeight, schechterRatio, angularDensityWeight, baked absMag, sbAmp. Galaxy-static values (PA rotation, absolute magnitude) are baked at upload, not recomputed per vertex. Identity is composed on the GPU from a per-draw `SourceUniforms.sourceCode` + `@builtin(instance_index)`, NOT baked per-vertex.
- **`galaxyPickRenderer.ts`**: r32uint pick texture. The fragment writes `(sourceCode << 26) | (localIdx + PICK_SENTINEL_OFFSET)`; see `src/data/selectionEncoding.ts` for the encoding (6 bits source, 26 bits localIdx, code 63 reserved as the all-ones sentinel). Source codes are append-only (the rule lives in `sources.ts`'s docstring) — same hygiene as enum values that get persisted to .bin, applied to POI-only codes too. Read the texture with `copyTextureToBuffer` for hover/click.
- **`textureAtlas.ts` + `texturedDiskRenderer.ts` + `shaders/texturedDisks/*.wesl`**: 2048×2048 atlas of 128×128 slots for galaxy thumbnails. LRU eviction.
- **`engine/subsystems/bitmapStreamSubsystem.ts`**: the shared atlas + fetch infrastructure — LRU clock, priority-queued concurrency-limited bitmap fetcher, and the `bitmapReady`/`bitmapFailed` memoisation pair. Enqueue is idempotent (don't re-add in-flight keys — see the module header for the bug history). Catalog- and atlas-agnostic; `engine/subsystems/galaxyAtlasSubsystem.ts` configures it with the galaxy thumbnail atlas's geometry and format. Thumbnail URLs are built by `src/utils/math/{sdss,dss}ThumbnailUrl.ts`: SDSS DR18 ImgCutout (CORS-safe) for SDSS galaxies; CDS hips2fits (CORS-safe DSS proxy) for 2MRS/GLADE.
- **`engine.ts`**: per-frame loop. Per-galaxy `apparentSizePx` gates thumbnail enqueue — but the inner loop hoists `Math.tan` and pre-computes `maxCamDistForVisibility` to avoid 2.5M trig calls per frame.
- **The frame's draw order lives in `engine/frame/frameOrder.ts`** (`FRAME_ORDER`), a hand-authored list expanded per frame by `expandFrameOrder.ts` into the steps the executor walks. A Layer's pass that no line names never draws — and that is caught at boot, not at runtime: `checkFrameOrder` cross-checks the list against the registered passes once, from `startLoop`, and throws before the first frame renders. GPU-timing slot names are not a second hand-authored list: `timedSlots.ts` derives them from that same `FRAME_ORDER` expansion, so the DebugPanel's slot table can never diverge from what the frame actually runs. A render line may declare `depth: { sample: <targetId> }` instead of `'clear'`/`'load'`; `executeFrame` never attaches that depth as its own pass's attachment and instead hands the step's passes `view.sampledDepth` — the source row's depth as a bound texture, plus the slab whose clear last wrote it (or the far-cleared 1×1 placeholder and a `null` row when nothing has cleared it yet this frame). The depth buffer holds only the LAST cleared row's value (one texture per target row, not per slab), so a step that needs its OWN row's depth, not a stranger's, compares `sampledDepth.row` to its own `view.slab` before drawing (`contactShadowsPass`).
- **A `{ kind: 'plan' }` line runs a `FrameContentPlanner` row, ahead of its own section's GPU steps** (`engine/frame/{createFramePlannerResultStore,runPlanSteps}.ts` + `engine/frame/planners/`): a CPU planner is a program line like a compute, sharing its section's `scope` — a `once` row plans over every view of the frame, a `perView` row plans one and is re-run for each. `renderFrame` runs every `once`-scope plan row before it schedules the sky captures (they read the settling vote) and before any encoder exists; a `perView` section's plan rows run per view, ahead of that view's own first GPU step. The answer lands on `ReadyFrameContext.plans` (`createFramePlannerResultStore()`, one store per frame, shared by every view the way `snapshot` itself is) — a pass reads it back with `ctx.snapshot.plans.get(planner, view)`, which THROWS on a miss rather than falling back to a stale or canvas-shaped answer. `checkFrameOrder` enforces at boot that every registered planner sits on exactly one `plan` line, that line's scope matches its section's, and a section's `plan` lines lead its other steps.
- **Aerial perspective is a per-frame froxel bake, then two sampled-depth reads** (`engine/frame/computes/aerialPerspectiveCompute.ts` + `engine/frame/encodeAtmosphereAerialPerspective.ts` + `gpu/renderers/atmosphere/aerialPerspectiveRenderer.ts` + `shaders/atmosphere/aerialPerspective/{bake,froxelSlices}.wesl` + `data/atmosphere/froxelVolume.ts`): while the camera is inside a body's shell, the `'aerial-perspective'` compute row marches one ray per screen texel of a 32×32×64 camera-local volume pair — in-scatter and transmittance, `rgba16float` — storing the running integral at each of the 64 slices, `FROXEL_SLICE_KM = 4` km apart, so the apply reads two texels instead of re-marching. Past the last slice the apply hands the pixel to the outside shell's per-pixel segment answer (the same LUT path the outside atmosphere draws), so the inside limb renders like the outside one and the volume's 32×32 screen resolution never touches a silhouette. The hand-off itself is a per-frame altitude cross-fade, not a hard cut: a `smoothstep` over horizon distance divided by the froxel bound takes the froxel answer alone below a ratio of 1.0 and the shell answer alone above 2.0, so the seam the cut would otherwise draw across the ground never appears. The residual is the shell's own (in-scatter is the LUT's whole-ray answer, so high terrain far out is over-fogged, as before). The bake also owns the frame's ONLY write of that body's shell uniform record: it runs in the SCENE section, per view, off the same `insideAtmosphere` row the apply draws on — each view is its own submit, so a view's bake lands before its own apply, so bake and apply unproject through one `slab.vp` and cannot disagree about which ray a froxel column belongs to. Five rows then read `foreground:0`'s depth through `view.sampledDepth`: the aerial apply (`passes/aerialPerspectivePass.ts`), which fogs each pixel to its own scene distance and falls back to the sky branch where the depth is still the far clear; and the orbit trails (`passes/orbitTrailsPass.ts`), where a trail point farther than the sampled surface fades out, hiding a trail behind terrain and meshes that the analytic occluder spheres miss. The trails unproject in the sampled row's own frame scaled to km (`sampledDepthKmFrame`), off that row's f64 `vp`, not the drawing view's. The two swap-target overlay rows read the same depth through the same helper (`engine/frame/overlaySceneOcclusion.ts`), so a scene-body caption and its leader line hide as a whole when the sampled surface at the subject's own position stands nearer than its near surface (`Label2D.occludeNearKm`, the subject's near surface in km; `Label2D.occludeSubjectPos`, since a lifted caption's own `worldPos` stands over OTHER terrain than its subject) — judged once, in the vertex stage, not per rendered pixel (a per-pixel verdict cut a caption in half wherever relief varied across its own screen footprint). The OUTSIDE-shell atmosphere is the fifth (`passes/atmosphereShellPass.ts` + `shaders/atmosphere/shell/fragment.wesl`): it classifies each ray by that depth rather than by the relief-floor sphere — finite depth ⇒ a ground ray, ended at `min(top exit, depth)` and drawn by the near wall; far depth ⇒ limb or sky, drawn by the far wall. The floor sphere only picks the sky-view LUT half now. Terrain standing above that floor at the limb used to miss it, so neither wall claimed it: a bright unextincted band, worst toward the terminator. The shell's pipeline carries NO depth state as a result — its step samples the depth rather than attaching it, so a body in front of the shell is dropped in the fragment (a sampled depth nearer than the shell entry), and `atmosphere-shell` left the probe capture roster, whose faces resolve no sampled depth.
- **`renderScheduler.ts` + `engine.ts` frame tail**: render-on-demand. `requestRender()` from event handlers wakes the loop; the frame body re-schedules only while `autoRotate || currentTween || hasAnyAxis || queue.inFlightCount > 0 || recent-fade` is true.
- **Earth surface virtual texture** (`utils/surfaceTiles/cutSurfaceTiles.ts` + `engine/subsystems/surfaceTileSubsystem.ts` + `gpu/renderers/bodies/surfaceTileRenderer.ts` + `gpu/resources/textureAtlas.ts` + `data/bodies/surfaceTileParams.ts`): detail patches streamed on top of Earth's whole-globe albedo once the screen wants more detail than the base texture (8192×4096, pyramid level 4) delivers. `cutSurfaceTiles.ts` is the pure per-frame quadtree walk — horizon reject, frustum reject, level-from-screen-density refine — that resolves BOTH products in one pass: `requests` (what to fetch) and `cut` (what to draw, each leaf's atlas residency already resolved via an injected ancestor-fallback lookup); its module header owns the algorithm, design rationale is in the plan and spec below, not restated here. `surfaceTileSubsystem.ts` turns the walk's fetch demand into atlas allocations and answers residency queries; `textureAtlas.ts` is the shared LRU slot atlas (also used by the galaxy thumbnail path) whose `allocate` returns `number | null`. `surfaceTileRenderer.ts` draws the resolved `cut` in one `drawIndexed` off a shared index template (`vertex_index`) and a `PatchInstance` per patch (`instance_index`) — positions displaced off the height atlas at mesh resolution `n = 64` (`textureLoad`, never a sampler — see the landmine below), no vertex buffer, no per-frame vertex upload, while the fragment stage takes its normal from the same lattice at full post density (geometry LOD and shading LOD are separate budgets, spec §7/§10) — directly over the base globe pipeline (`gpu/renderers/bodies/earthRenderer.ts`, `gpu/shaders/bodies/earth/fragment.wesl`), which F2 draws at the datum's inner bound so relief can never be occluded by it while the tile draw itself stays on the datum, with a `'nearer-or-equal'` depth compare so ties resolve in the tiles' favour — the base pipeline itself carries no atlas binding or per-fragment lookup; detail is a separate draw, not a blend. Design record: [`docs/superpowers/specs/2026-07-28-earth-surface-virtual-texture.md`](superpowers/specs/2026-07-28-earth-surface-virtual-texture.md), [`docs/superpowers/plans/2026-07-29-earth-surface-virtual-texture-a-to-d.md`](superpowers/plans/2026-07-29-earth-surface-virtual-texture-a-to-d.md), [`docs/superpowers/specs/2026-09-13-per-planet-terrain-design.md`](superpowers/specs/2026-09-13-per-planet-terrain-design.md).
- **The surface tile walk resolves TWO products, not one**: albedo (`rgba8unorm-srgb`, 512 px slots) and height (`rgba8unorm` Terrain-RGB codes decoded in `lattice.wesl`, 129-post slots, a 4128² atlas — 32 slots/row at `HEIGHT_POSTS_PER_TILE`, 1024 slots against albedo's 256). **Refinement is residency-blind** (R14): screen error and the manifest's bands alone decide the cut, and BOTH products inherit from the deepest resident ancestor — height via `resolveHeightLattice`, which hands the leaf the ancestor's slot plus its own sub-rect in posts (`levelDelta`, `originPosts`), exactly the lattice the ancestor draws because the bake decimates strictly (R1). Gating refinement on a leaf's own height tile (the pre-R14 rule) turned an atlas miss into a permanent hole: the allocator refuses when full and the refusal is never retried, and the base globe used to fade out below 150 km (F2 draws it always, at the inner bound). `balanceSurfaceCut` then steps neighbouring HEIGHT levels to within one of each other — it never adds or removes a leaf — except across a band's own edge, where the balance is deliberately dropped (band-capped, R12): F2's skirt, drawn on every edge of every patch, is what hides that multi-level step, not a finer bake. The leaf's sub-rect reaches the shader as `heightSlotOrigin` (slot origin + `originPosts`) and `heightCells` (`128 >> levelDelta`); `probe` also reads the resident ancestor's `subtreeMin/MaxM` and adds it — divided by `radiusM`, clamped at the patch's own corner chord (R15) — to that node's bounding sphere, so a displaced summit near a side plane is not culled with its datum patch while a base-level ancestor's Earth-wide range cannot inflate a z19 node.
- **`probe` culls with a bounding sphere against the frustum's side planes, and only then trusts a projected bbox**: the sphere (centre = patch centre, radius 1.5× the chord to the farthest corner, so skirts and relief up to half the patch fit, plus the clamped relief margin above) is the ONLY test a near-plane straddler gets — its NDC bbox is meaningless, and it is then treated as screen-filling. Before the sphere test a straddler skipped the frustum entirely, and the strip of ground BEHIND a tilted camera straddles the eye plane along its whole width: 887 z13 leaves and 1819 height requests at 300 km/60° over a whole-globe z13 band, and ~1100 leaves at 50 m altitude, none of them on screen. Now 39 and ~20 (`cutSurfaceTiles.test.ts`).- **Body render slabs** (`utils/camera/{composeBodySlabMvp,bodySlabCamLocal}.ts` + `engine/camera/bodyRelativePose.ts` + `gpu/renderers/bodies/**` + `gpu/shaders/bodies/**`): Earth, planets, textured bodies, rings, and the cloud/atmosphere shells draw from a per-body metre-native slab, not the galaxy catalog's Mpc frame. `bodyRelativePose.ts` is the ONE seam that converts the world-space (Mpc) camera into a body's fixed metre frame (`SCALE_UNITS.MPC_TO_M`, cancelling the shared heliocentric magnitude in Mpc first); every downstream compose (`composeBodySlabMvp`, `bodySlabCamLocal`) and every renderer/shader under `bodies/` takes that already-converted `eyeRelBodyM` and never re-touches the conversion — `tests/services/engine/camera/oneMpcSeam.test.ts` gates it structurally. The older Mpc-frame primitive, `composeBodyMvp.ts`, now serves only resolved star spheres (`starSpheresPass.ts`, `fieldStarSpherePass.ts`), which S4 deliberately keeps out of body slabs. Candidate rows are composed `SlabRow`s — store-fed bodies adapted through `bodySlabRowOf`, joined to every Layer's own `slabs?` rows (the blackHoles Layer's lens row among them) — each naming its host as `hostId: SlabHostId` (`BodyId | PlaceId`), not a bare `bodyId`: a Layer's slab need not be a body (the black hole's is a `PlaceId`).
- **Mesh bodies** (`gpu/renderers/bodies/meshBodyRenderer.ts` + `gpu/shaders/bodies/meshBody/*.wesl` + `engine/frame/passes/meshBodiesPass.ts`): lit triangle meshes in metres (the whale, the bowl of petunias) baked offline to `.mesh` by `tools/meshes/buildMeshes.ts`. One shared pipeline; per-body vertex/index buffers, three material textures (albedo sRGB, metal-rough + normal LINEAR), the body's own GGX-prefiltered reflection probe and a uniform buffer live in a `Map` keyed by body id (bind group 0), so each body's uniforms are written immediately before its own draw and no shared buffer can race a pending `submit`; bind group 1 is renderer-wide (samplers + the split-sum env-BRDF LUT). The material is a GGX metal/dielectric blend lit by the Sun as an analytic sphere light (`lib/pbr.wesl`'s `pbrDirectSphere`) plus the probe as environment (`envSplitSum`: specular by roughness mip, diffuse from the coarsest); there is no host-shine and no ambient floor — the probe is the ambient. `cullMode: 'none'` — both sources declare glTF `doubleSided` and a petal is a single sheet. A mesh body owns no slab row: it rides its HOST's body-m row (the way `ringsPass` rides Saturn's), so every direction the shader receives — `camPosLocal`, `sunDirLocal` — is in the HOST's fixed axes, not the body's own (`shaders/bodies/meshBody/io.wesl` is the contract). The probe cube is captured in those same host axes (`scheduleProbeCapture` rotates the face cameras by the host's orientation), so the fragment indexes it with host-axis `n`/`r` directly; a world-axis capture would read back rotated by the host's spin. Residency gates the draw: an id with no asset uploaded draws nothing rather than a placeholder.
- **GPU-memory ledger** (`services/gpu/memory/trackGpuMemory.ts`, installed by `engine/phases/initGpu.ts` right after the device resolves, always on): wraps `createBuffer`/`createTexture` in place, so every create site is tracked with no per-site change. Owner is the descriptor's `label` when set, else the basename of the first non-ledger stack frame (`utils/gpu/memory/ownerFromStack.ts`) — most create sites carry no label, so the fallback does most of the work. `gcReclaimed` (per owner, in the DebugPanel's Memory section and `npm run perf`'s MEMORY table) counts objects a `FinalizationRegistry` caught being garbage-collected without an explicit `destroy()` — the leak signal. Swap-chain textures (`context.getCurrentTexture()`) are never tracked; they aren't created via `device.createTexture`.
- **Caption/label occlusion reads alpha, not depth** (`gpu/renderers/labels/occlusionCoverageGroup.ts`): the shared depth buffer only ever holds the LAST painter-chain row's value (each row clears its own depth, spec §7.3), so overlay fragments (labels, marker lines, selection ring) fall off against `foreground:0`'s colour-texture ALPHA instead, which accumulates under OVER compositing across chain rows while depth does not survive them. `sceneTransmittance` (`shaders/lib/sceneDepth.wesl`) returns `1 - alpha` and each overlay scales its premultiplied output by it — a factor, not a threshold, because that alpha is ALSO the `foreground:0 → hdr` composite weight: one number, one meaning. A binary `alpha > 0.5` made it mean a second thing and broke whenever a translucent producer (a dense cloud deck, Earth's descent fade) crossed the line.

## Things that have bitten us before

- **WebGPU `queue.writeBuffer` race**: interleaving `writeBuffer` with `submit` in the same frame doesn't preserve order — bake per-instance data into the vertex buffer instead of a uniform you mutate per draw.
- **Selection halo on wrong galaxy**: same root cause — selection index must come from a per-vertex attribute, not a uniform updated mid-frame.
- **CORS on DSS thumbnails**: ESO's DSS endpoint blocks browsers. Use CDS hips2fits (`https://alasky.cds.unistra.fr/hips-image-services/hips2fits`).
- **Retry storms on failed thumbnails**: the engine has BOTH a `bitmapReady` and `bitmapFailed` Set — the per-frame gate must check both. The image queue's `enqueue` is idempotent for in-flight keys.
- **`<details>` element collapsing on hover**: keep the InfoCard's outer wrapper element identical across renders so React doesn't remount and reset the `open` state.
- **iOS WebGPU is stricter than Chrome's Tint — a bad shader freezes the _whole_ canvas**: `texture_1d` sampling (`textureSampleLevel` has no 1D overload) is one example WebKit rejects but Chrome accepts. Because all HDR passes share one command encoder, an invalid pipeline makes `encoder.finish()` produce an invalid command buffer and `queue.submit()` silently drops the _entire_ frame — the loop ticks and the camera moves, but nothing ever presents. Symptom: navigation/toggles do nothing on iOS while the React UI updates fine, no thrown errors. Diagnosis: `createShaderModuleWithDevLog` (in `shaderCompileLogger.ts`) prints the real `getCompilationInfo()` error + offending line. Store 1D LUTs as N×1 `texture_2d`.
- **Earth's tile detail has no page table to keep in sync — one CPU walk resolves residency, per leaf, per frame** (`cutSurfaceTiles.ts` + `surfaceTileSubsystem.ts`): the same quadtree walk that decides what to fetch also resolves each visible leaf's atlas slot inline, via an ancestor-fallback lookup, so there is exactly one place a residency bug can live instead of a walk plus a GPU-side table kept in sync with it. `surfaceTileRenderer.ts` then draws the resolved leaves with one `drawIndexed` off a shared index template and per-patch instance records, positions displaced off the height atlas in the vertex shader at mesh resolution `n = 64` (shading reads the same lattice at full post density), in a separate pass directly over the base globe — which F2 draws at the datum's inner bound, always, while the tile draw stays on the datum — with a `'nearer-or-equal'` depth compare so ties resolve in the tiles' favour.
- **A leaf with no resident tile anywhere in its ancestor chain is just absent from the cut — not a sentinel value**: `cutSurfaceTiles` drops such a leaf from `cut` entirely (its own tile, and every ancestor strictly deeper than the base level, unresident); the base globe already covers that ground — it is drawn at every altitude, never faded — and simply shows through wherever no detail patch draws over it, so every failure path (no manifest, no atlas, a 404, ground outside the cut, cold start) collapses to the same "nothing drawn" case rather than a placeholder state to maintain.
- **`textureSampleLevel`, never `textureSample`, for the Earth tile atlas read** (`surfaceTile/surfaceLighting.wesl`): the atlas has a single mip level so there is no level to select, the call sidesteps WGSL's uniformity requirement for implicit derivatives, and those derivatives would be wrong anyway — the atlas uv jumps discontinuously at a slot boundary, so `dpdx` there reads garbage across the seam.
- **The height atlas holds Terrain-RGB codes (`rgba8unorm`), read with `textureLoad`, never a sampler, and decoded in WGSL** (`lattice.wesl`'s `postHeightM`): `textureSample` is illegal in the vertex stage, and filtering encoded bytes blends codes, not heights — bilinear stays on decoded metres. The bitmap goes to the GPU with `copyExternalImageToTexture` and is never read back on the CPU: Brave, Safari and Firefox perturb canvas `getImageData`, which put spikes in the terrain. The bind-group layout declares `sampleType: 'unfilterable-float'`.
- **A height tile's row 0 is its NORTH row**, while the vertex template's `j` counts north from the patch anchor's SOUTH edge — `vertex.wesl` flips `j` when it builds the lattice position `p` it hands `latticeHeightM`.
- **`edgeCoarser` is one bit per edge and compares HEIGHT levels, not leaf levels** (R15): set means the neighbour's height level is exactly one coarser, so that edge samples the lattice at doubled stride — which IS the neighbour's own posts — clamped to the leaf's `cells` so a one-cell sub-rect never reads past itself. A step of two or more (R12's band seam) carries NO bit: no stride meets it. The bit says nothing about mesh density, which is unbalanced since R14 — **every patch skirts all four edges unconditionally**, and that ring, not the bit, is what hides a T-junction. See spec §6's R12 amendment and §7.3.
- **Never pass a storage-buffer struct BY VALUE into a WGSL helper**: on Adreno (Android Chrome 152) `patchVertexOffset(anchor: PatchInstance, …)` read the copy's `dLonRad`/`dLatRad` as ~0 while `vs` read the same fields directly without trouble, so every patch vertex landed on its SW corner and the tile grid rasterized only as skirt-length radial slivers. Valid WGSL, no validation error, correct on Metal, TS twin green. Pass the fields as scalars. Found by drawing the lattice straight to clip space (`clip = (2s−1, 2t−1)`), which takes the suspect position path out of the observation; zero-area geometry otherwise hides every colour probe.
- **The TS twins (`latticeHeightSample`, `surfaceNormalFromHeightCell`, `patchVertexOffsetM`) are the only testable statement of `vertex.wesl`'s/`surfaceLighting.wesl`'s WGSL contracts, not dead code** — they have no production caller by design (F2-R7); a deletion audit must not remove them.
- **Normals blend per-post central differences across the cell, not one gradient for the whole cell** (`lattice.wesl`'s `latticePostGradient`, fragment stage): a single gradient held constant across a bilinear cell drew visible facets at coarse levels (found at Everest in the eye-check). Each of a cell's four corner posts gets its own central difference (16 `textureLoad`s per fragment), one-sided/clamped at the leaf's sub-rect edge — no apron, no halo row in the tile — then the four post gradients blend across the cell. TWIN: `surfaceNormalFromHeightCell.ts`.
- **Night lights gate on the DATUM normal, never the terrain-shaded one**: `surfaceTile/fragmentEarth.wesl`'s emissive term keys "is the sun up" on `dot(Ng, l)`, `Ng` being `in.normalLocal` (the un-displaced sphere normal) — keying it on the displaced shading normal instead turns any slope facing away from the sun at local noon into "night" and lights it with the city-lights texture in broad daylight.
- **The horizon cap folds a node's relief headroom, the screen footprint is sized at its resident `subtreeMinM`, and a camera below the datum still plans a cut** (`cutSurfaceTiles.ts`): the mean-sphere cap `acos(radiusM / camLen)` widens by `acos(1 / (1 + relief))` per node; the footprint samples sit on the subtree's lowest ground, never the datum (Mars' datum is ~2.7 km under Gale, which left the cut two to three levels short near the ground); and there is no `camLen > radiusM` early return — a Hellas-basin- or Dead-Sea-class camera (below the datum) is legal and must not return an empty cut.
- **The base level is a function of the session's TIER, not a constant** (`baseLevelForTier.ts`, body-generic since the terrain F4 prep): the three whole-globe surface textures are 2048/4096/8192 px, i.e. levels 2/3/4 on the ladder, so "the level the base already delivers" differs per tier and is derived from the tier the body's `surface` slot actually committed (`bodySurfaceTier.ts` — the app-wide `state.tier` is only the request). A constant off the `large` ceiling made a default `medium` session stand down a level early and hand a z3 base to a z5 tile. The inversion uses an integer shift loop, never `Math.log2`: a fractional level makes every tile path a decimal and every `1 << (zWin - z)` span garbage.
- **The base level, the request floor and the bake floor are three different numbers**: the base level (above) is where `cutSurfaceTiles` roots its quadtree walk and what the engage gate compares against; the request floor is per band — `Math.max(band.min, baseLevel + 1)`, derived per session in `derivePlannerParams` (`surfaceTileSubsystem.ts`); the bake floor is `BAKE_MIN_LEVEL` in `tools/textures/buildSurfaceTiles.ts`, and the manifest is how the runtime hears about it. Rooting the walk at a band's request floor would make that band's leaves satisfy `zWin >= min` by construction, leaving the engage gate (`plan.zWin > baseLevel`) unsatisfiable against its own floor; reading the bake floor as a runtime floor would make a shallower re-bake appear to do nothing.
- **`TextureAtlas.allocate` can return `null`**: when every slot was already claimed earlier in the same frame, it refuses rather than evicts (a consumer that wants more slots than the atlas has — Earth's tile planner asks for ~107 against 64 — would otherwise evict and refetch its own working set every frame). Every caller must treat `null` as "skip this request," not retry it.
- **`copyExternalImageToTexture`'s `flipY` differs between the whole-globe upload and the atlas upload, on purpose**: whole-globe body bitmaps (`earthRenderer.ts`, `texturedBodyRenderer.ts`, `cloudShellRenderer.ts`) upload with `flipY: true` so texture v=0 lands on the image's south row, matching the mesh's south-first v. `TextureAtlas.uploadBitmap` — shared by the galaxy thumbnail atlas and Earth's tile atlas — uploads with `flipY: false`, so within a slot v=0 is the source bitmap's own top row (for an Earth tile, its north edge). A third case: `meshBodyRenderer.uploadTexture` also uploads unflipped, because a glTF asset's UVs already put v=0 at the image's top row — the bake tool copies them through untouched, so flipping here would flip the authored texture off its authored geometry. None of the three is wrong; they are different textures with different consumers, and the reconciliation between them lives on the CPU side, in the tile-index arithmetic (`earthTileXyForUv.ts`'s `1 - v` flip) and the fragment's matching `1 - in.uv.y`, not in either upload call.
- **Full-screen ray reconstruction through an inverse MVP must use the homogeneous far-point form**: `normalize(P.xyz - cam * P.w)` for `P = invMvp * vec4(xy, 0.0, 1.0)`, never divide by `w` first. Under reversed-Z, `z = 0` is the FAR plane, so a naive `(invMvp * clip).xyz / w` divides by `w -> 0` there and every ray degenerates to the same direction (a uniform grey veil); and any finite-`z` unprojected point sits only a few near-plane distances from the camera, so `p - cam` is a metres-scale difference of otherwise unit-scale f32 vectors that shimmers as the near plane shrinks on descent. See `lib/sceneDepthRay.wesl`'s `sceneRayDir`.
- **Orbit trails draw AFTER the body composite and hide themselves analytically** (`engine/frame/passes/orbitTrailsPass.ts`, the post-composite `(hdr, NEAR0)` step in `FRAME_ORDER`): the `foreground:0 → hdr` composite would otherwise cut a trail's NEAR arc along with its far one, so the trails accumulate into HDR after it and the conic fragment does its own occlusion — an eye→orbit-point segment test against the frame's OPAQUE bodies as spheres (`engine/frame/sceneOccluderSpheres.ts`, derivation in [`docs/references/orbit-trail-fragment-math.md`](references/orbit-trail-fragment-math.md)). Opaque, not drawn: the set is read off the same partitions the `foreground:0` sphere layers consume, so a 1–3 px planet — drawn, but as an additive glint — occludes nothing. A new opaque body type therefore occludes trails for free only if it lands in one of those partitions as a sphere sized at its `innerBoundRadiusM` (datum + min relief) — occluders take the inner bound because under-occluding is the safe failure, letting a trail peek through at the limb, where over-occluding would hide an arc it shouldn't; a mesh body occludes only through the sampled `foreground:0` depth its host row stamped, on purpose — its real silhouette, where its bounding sphere hid a whole disc of trail around it — and a disc still needs its own term.
- **Every pick draw binds its own complete `@group(0)`**: no pass may rely on an earlier pass's bind having been left set in the encoder — `CONTENT_PASSES` is a set with no order contract between its rows, so whichever pick draws land later inherit whatever the previous one happened to bind, not what their own shader expects. The two COSMO pick rows, `zone-of-avoidance` and `structure-markers`, were the last to bind their own camera group instead of trusting the encoder's leftover state.
- **NEAR0 overlay clip `w` must stay ≫ 1e-20** (`engine/frame/near0OverlayClipScale.ts` + `near0OverlayVpF32.ts`): the captions, leader lines and selection ring anchor in eye-relative **Mpc**, so a body 31 m away projects to `w ≈ 1e-21` — and the rasterizer floors `w` near 1e-20, i.e. ≈ 309 m out, shrinking the whole overlay uniformly about the screen centre and worsening on approach (the mesh/body/pick MVPs are in metres and never see it). Their upload matrices are therefore rescaled to clip metres; NDC is invariant under a uniform clip scale, but anything the shader divides by `clip.w` is not — the label em travels scaled (the NEAR0 `createLabelRenderer`'s `clipScale`, wired in `gpuHandleRegistry`) and the ring's near-plane pin compares in the same units.
