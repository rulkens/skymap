Skymap draws one fisheye disc for your dome system to project. Dome mode runs from the published site. To fly the dome from a phone, the dome’s computer runs Skymap itself: see [Run Skymap for a phone remote](#run-skymap-for-a-phone-remote).

## Open dome mode

1. On the computer that feeds your dome system, open Skymap with `?dome` before the `#`, in small letters and with no value: `skymap.rulkens.com/?dome#focus=body-saturn`. For a phone remote, open the address under [Pair a phone](#pair-a-phone) instead.
2. Make the window full screen: <Keys of="F11" />, or on a Mac <Keys of="Ctrl+Cmd+F" />.
3. Show the window on the output your dome system takes its fisheye from.
4. Dome mode opens with the interface hidden. <Keys of="Tab" /> shows it, flat over the disc where the audience sees it, and hides it again.

## Run Skymap for a phone remote

<Fact id="remote-relay" />

1. On the dome’s computer, install Node 24 or later and git.
2. Copy the repository and install its packages:
   ```
   git clone https://github.com/rulkens/skymap.git
   cd skymap
   npm install
   ```
3. Start the server. In a terminal on macOS or Linux:
   ```
   export VITE_DATA_BASE_URL=https://skymap-data.rulkens.com
   npm run dev -- --host
   ```
   On Windows, in PowerShell:
   ```
   $env:VITE_DATA_BASE_URL = "https://skymap-data.rulkens.com"
   npm run dev '--' --host
   ```
   PowerShell drops a bare `--`, so it is in quotes there. The first line makes the app load its catalogues and pictures from our data server, as the published site does. `--host` lets other devices reach the server. It prints a Network address for each network the computer is on, and a Remote line with the address a phone opens. The Local line must read port 5173, the one address our data server answers: if it reads another, close what holds 5173 and start again.
4. Leave the terminal open. Closing it stops the server, and the phone loses the dome.

### What the network needs

- **The phone reaches the dome’s computer** on port 5173, where it loads the remote page and sends its messages. Put both on the same Wi-Fi, or on networks routed to each other.
- **The dome’s computer lets the phone in.** Its firewall must accept connections to port 5173; if it asks about Node, allow it.
- **Only the dome’s computer needs the internet**, for our data server. The messages between phone and dome go through the dome’s computer and nowhere else.
- **The phone draws nothing itself.** The remote page is buttons and a drag pad, so the phone needs no WebGPU.

## Pair a phone

1. On the dome’s computer, open `http://localhost:5173/?dome&remote`, with the view you want after a `#`. Open it at `localhost`, on that computer itself: at a Network address the browser does not draw with WebGPU, and our data server does not answer it.
2. Make the window full screen and show it on the dome, as under [Open dome mode](#open-dome-mode).

3. On the phone, scan the flat QR code in the corner of the dome computer’s screen, or the card on the dome. A phone without a camera opens the Remote address the server printed and types the room code; Join works once all eight characters are in.
4. The phone reads Connected. The card leaves the dome, and the dome’s interface is hidden.

## Fly from the phone

The phone shows what the dome reports, so a tap shows on the phone once the dome has done it. The tiles below the Home button appear once the dome answers. A tile opens its sheet over the lower part of the page, and the drag pad above it keeps working; Close or Escape shuts the sheet. Starting a tour, an exhibit or a clip shuts it too, so the card with that show’s controls is in view.

## Add another phone

On a phone that is connected, tap Setup, then Add a phone. The dome shows the card again, with the same room code, until the new phone connects; a second tap hides it. Every connected phone can steer.

## When the connection drops

<Fact id="remote-lost" />

- **The phone sleeps or leaves the Wi-Fi.** It reads Dome not there, names its room code and offers Change code, and nothing it sends reaches the dome. It connects again by itself when it is back. The dome keeps its view.
- **The phone’s page is reloaded.** It joins the same room again: the code is in its address.
- **The dome’s page is reloaded.** It gets a new room code and shows the card again. On the phone, scan the new QR code, or tap Change code and type the new code.
- **The server stops.** When it is started again, the dome’s page reloads itself with a new room code. Pair the phones again.

## If the phone does not connect

- **The QR code opens a `localhost` address on the phone.** The server was started without `--host`. Stop it with <Keys of="Ctrl+C" /> and start it with the command under [Run Skymap for a phone remote](#run-skymap-for-a-phone-remote).
- **The phone’s browser cannot open the page.** The phone does not reach the dome’s computer: check that both are on the same network and that the firewall allows port 5173. A guest Wi-Fi often keeps its devices apart.
- **The phone reads Looking for the dome, then Dome not there.** The room code is not the one the dome shows, or the dome’s page came from skymap.rulkens.com, which has no relay, or the room already holds three phones.
- **The phone reads Dome needs a reload or Remote needs a reload.** The dome’s page and the phone’s page come from different versions of Skymap. Reload the page it names: tap Reload page on the phone, or reload the dome’s page and scan its new code.
- **The dome shows no card.** Its address has no `?remote`, or a phone has paired already: tap Add a phone on that phone.
- **The phone cannot read the card off the monitor.** The card is bent to the fisheye. Scan the flat QR code in the top left corner.
- **The QR code holds an address on another network.** On a computer with more than one network the QR code holds the first Network address. On the phone, open `http://` followed by the address on the phone’s network, `:5173/remote.html`, and type the room code.
- **The dome reads Skymap needs WebGPU.** Its page was opened at a Network address. Open it at `localhost`.

## Live or as a film

<Fact id="screens-no-capture" />

- **Live.** Show the browser window, full screen and with the interface hidden, on the output your system takes a fisheye from. Someone flies the app, from the dome’s computer or a phone, while the audience watches.
- **As a film.** The recorder writes a fisheye disc of 4,096 by 4,096 pixels at 30 or 60 frames a second, without sound.

What we would build for a dome, and what is still missing for one, is on [Domes and museums](/domes/#deliver).
